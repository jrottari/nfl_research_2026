Scope & method

What Run 0 actually measured

Run 0 is scripts/run_tiered_ablation.py --max-tier 1 --no-pbp --out-dir data/processed_tier1: leak-aware walk-forward evaluation (fit on every season before T, predict season T, never a random split) across two feature tiers, using each model's hardcoded constructor defaults.

Tier 0 is lag/trend/age/draft-capital features on the full 1999–2025 panel — 23 held-out seasons, 2003–2025. Tier 1 adds FantasyPros expert-consensus rank and ffverse opportunity/usage features, which restricts the usable panel to just 2024–2025 (that column's real coverage starts in 2021, not 2019 as originally assumed). Tiers 2–4 and in-fold hyperparameter tuning are separate, later runs and are out of scope for this report.

Before the numbers

Two real bugs the harness exposed

01 · season column silently became a string

Every as_of cutoff check against load_ff_opportunity's season column raised TypeError — it round-trips through parquet as a string, not an int. Fixed by coercing with pd.to_numeric in tier1.py.

02 · FantasyPros ranks were drawn from a mixed pool

FantasyPros reuses the ecr_type='ro' code across three incompatible boards — redraft-overall, redraft-IDP, and redraft-offense. Filtering on ecr_type alone silently blended all three, which is why the first pass of this ablation had Tom Brady's 2020 preseason rank at 677 and every model, including a plain random walk, "beating the market." Fixed by filtering on page_type == 'redraft-overall' instead (verified: McCaffrey #1 overall 2021, Jonathan Taylor #1 2022, Puka Nacua #1 2025). Both are covered by regression tests in test_tiered_features.py.

Isolating the feature effect from the panel effect

Comparing tier 1 to tier 0's full-panel row would confound two things: a shorter, more recent panel and genuinely new features. The control row separates them.

→

Ridge gets almost nothing from tier 1. Its linear form can't express the interactions (usage share × efficiency, points-over-expected × position) that carry most of tier 1's signal.

→

XGBoost is the closest challenger to the market, and beats it outright on Top-24 precision (0.734 vs 0.708) — the tree model builds real interactions between usage/opportunity and consensus rank that Ridge structurally cannot.

→

Nobody beats the market on MAE, RMSE, Spearman, or VORP-weighted MAE. That's the expected, healthy result — professional consensus rankings should be hard to beat. (ecr_projection, FantasyPros' point-projection column, is never populated in the cached pull, so Market Consensus runs on its log-rank regression fallback alone — and still wins.)

Out of scope for this report

What Run 0 doesn't tell you

  • Tiers 2–4 are implemented, point-in-time guarded, and unit-tested, but were not part of this run — that's a separate ablation pass.
  • In-fold hyperparameter tuning (--tune, nested walk-forward GridSearchCV for Ridge/XGBoost) exists in the harness but was off for Run 0 — every model above used its hardcoded constructor defaults.
  • PBP-derived features (air yards share, WOPR, red-zone shares) require the large play-by-play pull, which Run 0 skipped via --no-pbp.

Reproducing Run 0

python scripts/run_tiered_ablation.py --max-tier 1 --no-pbp --out-dir data/processed_tier1

Writes tiered_forecasting_panel.parquet, tiered_ablation_predictions.csv, tiered_ablation_scores.csv, and one tiered_ablation_<metric>.csv per metric family. Raw nflverse/ffverse pulls are cached to data/cache/*.parquet, so subsequent runs are network-free.
